# Серверные конфигурации для n8n на VPS

В этом документе описаны минимальная и максимальная серверные конфигурации для размещения архитектуры n8n на виртуальном выделенном сервере (VPS) одного провайдера. Конфигурации рассчитаны на обслуживание от 100 до 1 000 уникальных пользователей в день.

## 1. Допущения

*   **Активность пользователей:** Предполагается, что «уникальный пользователь в день» запускает умеренное количество выполнений рабочих процессов за день.
*   **Сложность рабочих процессов:** Предполагается, что рабочие процессы имеют среднюю сложность, без чрезмерной обработки данных или длительных задач.
*   **Провайдер VPS:** Конфигурации основаны на типичных предложениях VPS-провайдеров (например, DigitalOcean, Linode, Vultr).
*   **Масштабируемость:** Архитектура допускает как вертикальное масштабирование (увеличение ресурсов сервера), так и горизонтальное масштабирование (добавление дополнительных серверов n8n).

## 2. Минимальная конфигурация (100 уникальных пользователей в день)

Данная конфигурация подходит для небольшой пользовательской базы с умеренной активностью.

| Компонент            | vCPU  | RAM      | Хранилище (SSD) | Примечания                                  |
| -------------------- | ----- | -------- | --------------- | ------------------------------------------- |
| **Load Balancer**    | 1     | 1 GB     | 25 GB           | Может быть небольшой VPS с NGINX.           |
| **n8n Server 1**     | 1     | 2 GB     | 50 GB           | Минимальная рекомендация для n8n.           |
| **n8n Server 2**     | 1     | 2 GB     | 50 GB           | Обеспечивает отказоустойчивость.            |
| **PostgreSQL DB**    | 1     | 1 GB     | 50 GB           | Объём зависит от журналов выполнений.       |
| **Monitoring Stack** | 1     | 2 GB     | 50 GB           | Prometheus, Grafana, Loki и др.             |
| **Итого**            | **5** | **8 GB** | **225 GB**      |                                             |

## 3. Максимальная конфигурация (1 000 уникальных пользователей в день)

Данная конфигурация рассчитана на более крупную пользовательскую базу с более частым и потенциально более сложным выполнением рабочих процессов.

| Компонент            | vCPU   | RAM       | Хранилище (SSD) | Примечания                                                       |
| -------------------- | ------ | --------- | --------------- | ---------------------------------------------------------------- |
| **Load Balancer**    | 2      | 4 GB      | 80 GB           | Для обработки возросшего трафика.                                |
| **n8n Server 1**     | 2      | 4 GB      | 160 GB          | Больше ресурсов для выполнения рабочих процессов.               |
| **n8n Server 2**     | 2      | 4 GB      | 160 GB          | Обеспечивает отказоустойчивость и обрабатывает большую нагрузку. |
| **PostgreSQL DB**    | 2      | 4 GB      | 250 GB+         | Увеличенный объём хранилища для журналов и рабочих процессов.   |
| **Monitoring Stack** | 2      | 4 GB      | 100 GB          | Prometheus, Grafana, Loki и др.                                  |
| **Итого**            | **10** | **20 GB** | **750 GB+**     |                                                                  |

## 4. Рекомендации по масштабированию

*   **База данных:** База данных PostgreSQL может стать узким местом. Для максимальной конфигурации рассмотрите использование управляемого сервиса баз данных от VPS-провайдера, если он доступен, поскольку такие сервисы часто обеспечивают лучшую производительность и автоматическое резервное копирование.
*   **Хранилище:** Объём хранилища для базы данных PostgreSQL в значительной степени зависит от количества выполнений рабочих процессов и объёма записываемых данных. Отслеживайте использование дискового пространства и будьте готовы к его увеличению.
*   **Горизонтальное масштабирование:** Если двух серверов n8n недостаточно, можно добавить дополнительные экземпляры n8n в `docker-compose.yml` и `nginx.conf` для дальнейшего распределения нагрузки.
*   **Мониторинг:** Настройте мониторинг всех серверов для отслеживания использования CPU, RAM и дискового пространства, чтобы своевременно выявлять узкие места и определять момент для масштабирования.

## 5. Доступ к Grafana

Grafana будет доступна по адресу `http://<your_server_ip>:8181`. Для входа используйте учётные данные по умолчанию:
*   **Имя пользователя:** admin
*   **Пароль:** grafana

После первого входа в систему вам будет предложено сменить пароль.
